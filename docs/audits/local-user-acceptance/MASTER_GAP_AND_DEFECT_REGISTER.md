## 1. Discovered Defects & Verified Fixes

### Defect `DEF-NET-001`: Hardcoded Backend Port in Frontend API Client
- **Severity:** HIGH (P1)
- **Module:** Architecture & Network Transport
- **File Affected:** [`src/services/apiClient.ts`](file:///D:/i2A_School%20ERP%20&%20Managment/src/services/apiClient.ts)
- **Root Cause:**  
  `apiClient.ts` previously defined:
  ```ts
  const API_BASE_URL = import.meta.env.VITE_API_BASE_URL || 'http://localhost:5000/api';
  ```
  When Vite launched on dynamic ports (e.g., 5176 or 5177) and the backend ran on custom ports or behind Vite's built-in `/api` proxy, browser requests attempted direct calls to `http://localhost:5000/api`, triggering `net::ERR_CONNECTION_REFUSED`.
- **Implementation Fix:**  
  Changed the fallback from the hardcoded localhost URL to `/api`:
  ```ts
  const API_BASE_URL = import.meta.env.VITE_API_BASE_URL || '/api';
  ```
  This allows Vite dev server's proxy configuration in `vite.config.ts` to seamlessly route all `/api` traffic to the backend, regardless of which local port is active.
- **Verification Evidence:**  
  All 13 roles in `scripts/run-complete-localhost-user-simulation.js` and all 7 chains in `scripts/run-cross-module-acceptance.js` connected and authenticated with zero connection refused errors.
- **Status:** **RESOLVED & CERTIFIED**

### Defect `DEF-SCH-001`: Parameter Key Mismatch in Online Admission Public Route
- **Severity:** MEDIUM (P2)
- **Module:** Module E (Student Admissions)
- **File Affected:** [`scripts/run-cross-module-acceptance.js`](file:///D:/i2A_School%20ERP%20&%20Managment/scripts/run-cross-module-acceptance.js) / [`server/routes/admissions.js`](file:///D:/i2A_School%20ERP%20&%20Managment/server/routes/admissions.js)
- **Root Cause:**  
  `server/routes/admissions.js` expects `{ phone, email, applyingClass }`, whereas legacy test runners submitted `{ parentPhone, parentEmail, gradeApplying }`, triggering a `400 Bad Request` schema rejection.
- **Implementation Fix:**  
  Normalized test runner payloads to strictly adhere to server schema requirements (`phone`, `email`, `applyingClass`).
- **Verification Evidence:**  
  `CHAIN-01` now passes with `201 Created` and application ID logged.
- **Status:** **RESOLVED & CERTIFIED**

### Defect `DEF-FEE-001`: Fee Receipt Key Inconsistency (`receiptNo` vs `receiptNumber`)
- **Severity:** LOW (P3)
- **Module:** Module L (Fees & Invoicing)
- **File Affected:** [`server/routes/fees.js`](file:///D:/i2A_School%20ERP%20&%20Managment/server/routes/fees.js)
- **Root Cause:**  
  The receipt response object generated by `POST /api/fees/receipts/collect` uses `receiptNo: 'INV-2026-...'`, whereas consumer code accessed `receipt.receiptNumber`, leading to undefined receipt numbers in client references.
- **Implementation Fix:**  
  Updated client readers to resolve `feeCollectJson.receipt?.receiptNo || feeCollectJson.receipt?.receiptNumber`.
- **Verification Evidence:**  
  `CHAIN-02` successfully captured receipt `INV-2026-432063`.
- **Status:** **RESOLVED & CERTIFIED**

## 3. Security Boundary & Gate Verification

- **Database Safety Preflight:** Verified 9 / 9 tests in `src/__tests__/DatabaseSafetyPreflight.test.ts` connecting strictly to `i2a_schoolos_synthetic_test`.
- **Production Database Isolation:** `i2a_schoolos` and `i2a_schoolos_test` were verified completely unaccessed and unmutated.
