## 3. Delivery Status Classification Framework

`i2A SchoolOS` strictly enforces three distinct delivery states:

1. **`SIMULATED_TEST_SINK` (`VERIFIED_SIMULATED_EMAIL`):**
   - Captured in `localEmailSink` in memory.
   - Used during development, regression testing, and CI/CD pipelines.
   - Guarantees zero credential exposure and zero spamming of external recipients.
2. **`PROVIDER_ACCEPTED`:**
   - Handed off to Google Workspace / Gmail SMTP with HTTP/SMTP `250 OK`.
   - Message ID generated by the upstream relay.
3. **`VERIFIED_DELIVERED`:**
   - Certified receipt in recipient mailbox (confirmed via webhook or IMAP check).
   - Classified as `LIVE_GMAIL_NOT_VERIFIED` until staging pilot secrets are injected.

## 4. Error Handling, Retries & Header Injection Defenses

### A. Anti-CRLF Header Injection Protection
Malicious input containing carriage returns (`\r`) or line feeds (`\n`) in recipient addresses or subject lines could split SMTP headers and inject hidden `Bcc:` recipients. `emailService.js` actively sanitizes all headers:
```javascript
export function sanitizeHeader(val) {
  if (!val) return '';
  return String(val).replace(/[\r\n]+/g, ' ').trim();
}
```

### B. Transient Transport Error Retry Logic
If a network timeout occurs during outbound SMTP delivery, the adapter retries up to 2 times with a 500ms backoff before marking delivery as `FAILED`.

### C. Safe Fallback Behavior
If SMTP credentials are absent or invalid, the system automatically falls back to `localEmailSink` without crashing the Express server, ensuring system stability.

## 5. Safe Private Staging Setup Instructions (Live Gmail)

To enable live Google Workspace / Gmail delivery in a secure private staging environment:

> [!CAUTION]
> **Never commit `.env` or paste Gmail passwords into chat!**  
> Use Google Account 2-Step Verification and generate a dedicated Application Password.

### Step-by-Step Setup:
1. Log into the school's outbound Gmail/Google Workspace administrator account.
2. Go to **Security** → **2-Step Verification** → **App Passwords**.
3. Create a new App Password named `i2A SchoolOS Staging`.
4. Add the following lines to your private staging server's `.env` file:
   ```ini
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=465
   SMTP_SECURE=true
   SMTP_USER=your-service-account@yourdomain.com
   SMTP_PASS=xxxx yyyy zzzz wwww
   SMTP_FROM="i2A SchoolOS" <your-service-account@yourdomain.com>
   PUBLIC_APP_URL=https://staging.yourdomain.com
   ```
5. Run the built-in diagnostic test to confirm connectivity:
   ```powershell
   node -e "const { verifySmtpConnection } = require('./server/services/emailService'); verifySmtpConnection().then(console.log);"
   ```
6. Observe: `{ "verified": true, "reason": "CONNECTED", "error": null }`.
