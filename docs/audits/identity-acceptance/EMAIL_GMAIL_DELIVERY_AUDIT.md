## 1. Email Service Architecture

i2A SchoolOS employs a hardened email dispatch service (`emailService.js`) designed to guarantee deterministic, leak-free automated testing while supporting production Gmail and SMTP configurations.

### Configuration Parameters
- `SMTP_HOST`: Hostname of SMTP relay (e.g. `smtp.gmail.com`).
- `SMTP_PORT`: Port (typically `587` for STARTTLS or `465` for SSL).
- `SMTP_USER`: Service username or Gmail address.
- `SMTP_PASS`: Gmail App Password or SMTP authorization secret.
- `SMTP_FROM`: Approved sender address (e.g. `noreply@schoolos.in`).

### Provider Mode Resolution (`getEmailProviderMode()`)
```
if (SMTP_HOST && SMTP_USER && SMTP_PASS)
    ├── SMTP_HOST includes "gmail.com"  --> 'GMAIL_SMTP'
    └── other host                      --> 'CUSTOM_SMTP'
else (Default or NODE_ENV === 'test')   --> 'TEST_SINK'
```

The application never falsely claims an email was delivered to an external inbox when in test mode.

## 3. Dispatched Template Verification

Every email template generated by `emailService.js` was inspected for content, security notices, and formatting:

1. **Student Account Activation (`STUDENT_INVITATION`):**
   - Verified student name, class, section, single-use activation link, and explicit expiration date.
   - Contains security disclaimer: *"Do not share this link with anyone"*.
2. **Parent Portal Invitation (`PARENT_INVITATION`):**
   - Verified parent greeting, linked child name, class, and portal capabilities.
3. **Staff Workforce Invitation (`STAFF_INVITATION`):**
   - Verified staff name, assigned role, department, and secure activation link.
4. **Password Reset OTP (`PASSWORD_RESET_OTP`):**
   - Verified 6-digit numeric verification code in high-contrast formatted box.
   - 10-minute expiry warning and fraud advisory notice.
5. **Password Changed Security Alert (`PASSWORD_CHANGED_ALERT`):**
   - Verified timestamped notification alerting user that their password was updated.
   - Includes urgent instructions if the user did not initiate the change.

## 4. Security & Abuse Defenses

1. **Anti-CRLF Header Injection:**  
   `sanitizeHeader()` and `validateEmailAddress()` strictly reject carriage return (`\r`) or line feed (`\n`) characters in recipient emails or subjects. An adversarial injection attempt (`attacker@evil.com\r\nBcc: victim@school.in`) was executed and rejected with HTTP 400.
2. **RFC 5322 Email Validation:**  
   Malformed email strings are blocked before queuing.
3. **Zero Credential Logging:**  
   Raw passwords, database connection strings, and plaintext invitation tokens are excluded from all email payloads and server log streams.
